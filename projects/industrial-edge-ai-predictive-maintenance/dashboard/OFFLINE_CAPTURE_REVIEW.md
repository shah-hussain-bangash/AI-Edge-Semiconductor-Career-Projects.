# Local offline capture manifest review

Telemetry now includes Review an offline capture manifest, separate from committed synthetic observations and demonstration charts. Select `manifest.json` from a folder produced by the existing `phase-01-hardware/scripts/prepare_capture.py` adapter. The file is read only in the browser. No upload, service request, saved record, sensor chart, incident, binding or equipment command is created. Reload or Clear manifest removes the review; selecting another file clears the previous review immediately.

The manifest summary is metadata structure review, not package verification. Input/accepted/quarantined row counts, sequence gaps, creation time, source type and file-reference hashes are declarations in the selected file. That summary does not read other package files. The optional quarantine viewer below checks a separately selected quarantine file only; neither view reads the capture CSV, attachment or accepted observations, recomputes the transformation, inspects sensor values, verifies calibration or authenticates a physical source. Measured/replayed declarations remain exactly labelled and are never converted to synthetic. No observations are admitted to the dashboard. The original 30 selected hardware products are unchanged.

## Quarantine reason counts and local filters

After a quarantine file is supported, the Reason selector lists the codes present with counts from the complete selected file. Search matches literal trimmed, case-insensitive text across the CSV line label, reason code and plain explanation. Reason and search combine, preserve original source order and reset paging to the first matching page. Counts distinguish matching entries from the complete file; no matches offers Clear filters, which restores search focus. Empty logs leave search and reason controls disabled and do not imply sensor health. Reason counts describe adapter classifications, not confirmed physical faults.

Filters change only the displayed cards. Complete quarantine export retains every entry and its original review context, even with zero matches; private search text is not added to the export. Clear review, a new or invalid file, manifest replacement and reload remove filters and reason counts. No preferences, file data or filter text are stored or sent to the service. Search is bounded to 160 characters. The disposable browser suite exercises mixed adapter-generated reasons, combined filters, literal matching, filtered paging, zero-match full export, reset focus, replacement/race boundaries, auditor access and responsive layouts.

Use the existing offline adapter's `verify` command on the complete evidence folder before any later integration. See [the offline capture handoff](../phase-01-hardware/docs/OFFLINE_CAPTURE_HANDOFF.md). Even successful package consistency is not a signature, trusted source, equipment authorization or physical acceptance. Historical files do not establish current connection. A false adapter `requires_review` flag is displayed as Not requested—not as acceptance; accepted-format rows can still have invalid sensor groups.

The viewer supports the exact `edgeops-v1-csv-to-v2-evidence-v1` manifest field set, operator-declared synthetic/measured/replayed source labels and unavailable boot identity. Verification/readiness flags must all be false. Counts must be typed nonnegative integers, reconcile and stay within 10,000 rows; sequence gaps are bounded and cannot exist with fewer than two accepted rows. The review flag must agree with quarantine/no-accepted-row conditions. Creation time must be a calendar-valid UTC adapter timestamp. Exactly four file references are accepted with bounded typed sizes and lowercase SHA-256 strings; zero/nonzero observation/quarantine sizes must agree with declared counts. These checks do not prove the referenced files exist or match their hashes.

The JSON input cap is 64 KiB. A bounded parser refuses duplicate keys (including escaped spellings), malformed JSON, extra trailing content, nonfinite numbers, nesting beyond eight levels and excessive tokens. Exact field sets reject unknown metadata instead of silently interpreting it. Invalid input leaves no previous counts, references or export. SHA-256 of the selected manifest itself is computed locally; it is a fingerprint, not a signature.

Export metadata review preserves the exact parsed manifest, selected file name/bytes/hash and local browser review time. It explicitly reports `manifest_structure_checked=true`, while package-file checking, transformation recomputation, source authentication, upload, persistence, physical-source verification, calibration, connection, ingestion readiness, equipment and production authority remain false. Delayed reads cannot replace a newer selection or restore a cleared review. No browser storage is used.

The disposable browser test generates manifests with the actual offline adapter from synthetic CSV fixtures. It exercises synthetic/measured/replayed declarations, empty and quarantined captures, exact export/fingerprint/scope, unsupported counts/provenance/timestamps/files/claims, duplicate keys/depth/encoding/size/trailing-content refusal, no service calls or ingestion, clear/new-file races, auditor access, contrast, five widths and reload clearing. Those fixtures are software exercises, not measured hardware evidence. Real connection, electrical review, acquisition accuracy, calibration and industrial acceptance remain pending.

## Selected quarantine-file review

Inspect quarantined-row reasons locally becomes available after a supported manifest is loaded. Choose its original `quarantine.jsonl`. The file must match the manifest's exact byte count and SHA-256 reference; the viewer then reconciles the entry count and accepts only the adapter's two-field `{csv_line, reason}` records. This checks one selected file against an unauthenticated manifest. It is not complete-package integrity, source transformation recomputation, independent fault diagnosis or physical acceptance. The existing offline verifier remains required for the entire folder.

The viewer limit is 2 MiB and 10,000 entries. UTF-8 JSON lines use LF/CRLF, with at most one final line terminator; blank records and lines over 256 characters are refused. Duplicate/extra fields, unsupported reason codes and noninteger/boolean/duplicate/reordered line references are refused. `csv_line` is the CSV reader's ending physical line, not a telemetry sequence or observation ID. It must increase and remain within the capture's 16 MiB line-count bound. Supported codes cover CSV/identity/counter/time/boolean/numeric validation, aggregate sensor validity and unresolved sequence/uptime/receipt-order boundaries. The last category does not prove a reboot or packet loss.

Up to 50 entries are shown per page. Previous/next controls and explicit entry ranges preserve source order; Export complete quarantine review always retains all entries, both selected-file and manifest fingerprints, the declared source type, and false package/source/physical/ingestion/equipment/production authority. It records `selected_file_reference_matched=true` separately from `package_integrity_verified=false`. Empty matching logs do not imply healthy sensors or readiness: accepted-format rows may still contain invalid sensor groups. Other files and existing stored readings are unchanged.

Clear quarantine review removes its entries/references/export and restores picker focus. A new selection clears previous results before checking. New/invalid/cleared manifests and reload also remove the quarantine context; delayed reads cannot attach old reasons to a newer file or manifest. No file or operational record is uploaded/stored. The expanded browser suite uses real adapter-generated one-entry, empty and 101-entry fixtures, checks hashes/lengths and complete paged exports, malformed or forged-reference records, unsupported reasons, stale-read/manifest clearing, no ingestion, auditor boundaries, contrast and five widths. Windows fixtures preserve CSV bytes directly so physical line references are not changed by newline translation.
